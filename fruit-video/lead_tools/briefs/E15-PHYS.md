## What it is for
Episode 15 has a crane that lowers a whole building onto another (props fly, a tower squats, cables whip), a hanging banner that unrolls, a falling org chart of boxes, forty clones, a pile of pizza boxes. Until now every collapse in this series was hand-authored waypoints. This episode they are simulated, AND the simulation tells the sound builder exactly when and how hard things hit, so a clatter lands on the frame it is drawn.

## Requirements
`phys2d.js` is a single dependency-free file that works in BOTH the browser (`window.PHYS2D`) and node (`module.exports`). No DOM, no `Math.random`, no wall clock. Everything deterministic: same code and seed give bit-identical results on every machine and every run.
1. **Bodies**: dynamic, static and kinematic (a kinematic body follows a scripted path `pose(t)` and pushes dynamic ones: the crane hook, the descending building, a moving wall); shapes: circle, box (half extents), convex polygon (up to 8 vertices), plus compound bodies (several shapes on one body: a chair is a seat box and a back box); mass from density; friction and restitution per material; sleeping (a body at rest goes to sleep so stacks stay put); collision filtering (groups/masks); user `tag` (string) and `mat` (material name: 'wood', 'metal', 'cardboard', 'plastic', 'glass', 'fabric', 'ceramic', 'rubber', 'concrete' ...) and `data` (any object the scene wants, e.g. which sprite to draw).
2. **Solver**: fixed step 1/240 s, sequential impulses with warm starting (the Box2D-lite family: SAT or GJK for convex polygons, contact manifolds with up to two points, accumulated impulses, friction, restitution with a velocity threshold, position correction with slop), 8 velocity and 3 position iterations by default (configurable). Stacks of 8 boxes must stand still; a pyramid of 21 boxes must be stable for 10 seconds; a box dropped on a slope slides according to friction; a ball bounces to a believable height.
3. **Joints**: distance (rigid or spring: stiffness, damping), revolute/pin (with optional limits and motor), weld, mouse/target joint, and **ropes** (a chain of N segments with distance constraints and bending resistance, one end pinned to a kinematic body (the crane hook), the other end attached to a body) and a simple **cloth strip** (a banner: a 1D chain of vertical strips or a small verlet grid of points pinned along the top edge, with wind and gravity; returns point positions per sample for a renderer to draw as a mesh), both stable at 240 Hz. Breakable joints (a threshold impulse) are a bonus.
4. **World API** (keep it small and documented in `GUIDE_PHYS.md`):
   ```js
   const w = PHYS2D.world({ gravity: [0, 980], dt: 1/240, seed: 1 });      // y points down (canvas units); 980 units/s^2 means 1 unit = 1 mm... choose and document; the scenes use the dollhouse scale
   const b = w.body({ type: 'dynamic', shapes: [{ box: [hw, hh], offset: [0, 0], angle: 0, density: 1, friction: .6, restitution: .1 }], x, y, angle, vx, vy, w, mat: 'wood', tag: 'chair', data: {...} });
   w.joint({ type: 'rope'|'distance'|'pin'|'weld'|'spring', a, b, anchorA: [x,y], anchorB: [x,y], ... });
   w.run(T, { sampleHz: 120 });     // simulate 0..T once, store one transform per body per sample (Float32Array)
   w.at(t) -> { bodies: [{ id, x, y, angle, vx, vy, awake }], ... } // interpolated; pure function of t; w.pose(id, t) for one body
   w.events  // [{ t, kind: 'hit'|'slide'|'roll'|'break', a: id, b: id, tagA, tagB, matA, matB, x, y, mag, speed }]  collisions with impulse above a threshold, thinned: no more than one per body pair per 60 ms, magnitude normalised 0..1
   ```
   `kinematic` bodies take `pose: t => ({ x, y, angle })`; scripted at every substep.
5. **Events for the sound** (the point of the library): `w.events` as above, plus `PHYS2D.eventsToFoley(events, { sceneStart })` that turns them into the compact JSON the sound builder reads: `[{ t, name: 'phys', mat: 'wood+metal', mag: 0.62, pan: -0.3, x, y }]` with `pan` from x (given the scene's screen width or camera mapping passed in options) and a cap of about 120 events per scene (keep the loudest, always keep the first impact of each body). `tools_phys_events.js` is the node CLI: `node tools_phys_events.js <ep> ` loads every module listed in `build/ep<ep>/phys_sims.json` (a map of scene id to the path of a DOM-free sim module that exports `build()` returning `{ world, T, screen: { w, h, cx, cam } , sceneStart? }`), runs them, adds the scene start times from `build/ep<ep>/timeline.json`, and writes `build/ep<ep>/phys_events.json` (absolute times). Test it on your own demo sim.
6. **Performance**: 150 bodies, 8 s, with 2 ropes of 24 segments: `w.run` under 1.2 s in node on this machine, and under 2 s in Chromium. `w.at(t)` is O(bodies) and allocation-light (reuse buffers: it is called several times per frame, in 4 worker pages).
7. **Determinism and purity**: building a world twice gives identical `at(t)` for any t (assert it in the test with a hash of 100 sampled states).

## Quality notes
Prefer robustness over cleverness: a boring solver that never explodes beats a clever one that does. Clamp velocities, cap the angular speed, cap penetration correction, cap the number of contact points. Test with heavy-on-light (a 50x mass ratio) and with thin boxes (tunnelling: use sub-stepping or swept tests for fast small bodies). Matching the feel of a cartoon (slightly floaty, bouncy, soft contacts) is better than strict realism: expose `w.feel = { bounce: 1.0, soft: 0.0 }` knobs.
Work in chunks of at most about 300 lines per edit and run `node phys2d_test.js` after each, so a usage-limit stop loses nothing.

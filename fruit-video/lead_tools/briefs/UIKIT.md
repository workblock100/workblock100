## Why this exists
The user keeps seeing text that is "off": a sign-in sheet drawn upside down, names printed over each other, posters sliced by the frame edge, labels not centred in their pills, text off the ruled lines of a page, letter-spaced titles shifted a few pixels left. Our old audit never looked at text. The new gate (`txaudit.js`) records every string drawn on the picture with its true on-screen box and fails mirrored, upside-down, tilted, cut-off, overlapping and container-breaking text. Your job is the other half: a small library of drawing helpers that make good alignment the default, so scene builders cannot easily get it wrong, plus a test episode that proves both the helpers and the gate work.

## `ui.js`: `window.UI` (plain functions drawing on the current `ctx`, in whatever transform the caller has set)
All drawing goes through `text()` (engine.js) so outlines, shadows and the gate's options work. Every string must be *measured*, never guessed. Fonts in use: `Nunito` (variable weight 200-1000, the body face, mostly 900), `Bangers` (display, weight 400), `Lucky` (Luckiest Guy, weight 400). Cache font metrics per font (cap height from "H", x height from "x") measured once on a scratch canvas at a large size.
Options common to everything: `size, font, weight, italic, fill, stroke, lw, spacing (letter spacing px), alpha, rot, shadow, hero (default true: the viewer must read it; pass false for set dressing), id, tilt, crop, grp` (these are passed straight to `text()`'s options object, the gate reads them from there).

Required functions (names fixed; add more if useful):
1. `UI.metrics(font, weight, italic)` -> `{cap, x, asc, desc}` as fractions of the font size.
2. `UI.fit(str, maxW, o)` -> `{size, w, overflow}`: the largest size <= `o.size` (down to `o.min`, default 0.6 of size) whose measured width (with spacing) is <= maxW. NEVER squish. If even the minimum overflows, set `overflow:true` and, when `REG.on`, push `REG.errors` "text does not fit: ...".
3. `UI.label(str, cx, cy, o)`: one line, centred horizontally on its INK box (not its advance box) at `cx`, and centred vertically on its CAP BAND at `cy` (baseline = cy + cap*size/2, `textBaseline = 'alphabetic'`). `o.align` 'left' | 'right' anchors the ink edge at `cx` instead. `o.maxW` fits by shrinking (UI.fit). Pass `center: true` and `cid` (when inside a container) so the gate verifies the centring. Compensate for `letterSpacing` (it adds a gap after the last glyph; `text()` already corrects half a gap for centred text when `EP.textGate` is set, so do not correct twice; verify with the gate). Returns `{x0,y0,x1,y1,size}` (ink box in local coordinates).
4. `UI.lines(arr, x, y, o)`: a block of lines on a baseline grid (`o.lh`, default 1.2 x size), `o.align`; returns the boxes. `UI.wrap(str, maxW, o)` -> lines (greedy, by words, never breaks inside a word unless one word is wider than maxW, then it shrinks). `UI.para(str, box, o)`: wrap into `[x,y,w,h]`, shrink the size until the block fits the height, vertical align 'top'|'middle'|'bottom', returns `{size, lines, boxes}`.
5. `UI.panel(box, o)` (`box = [x,y,w,h]` in local coordinates): rounded rect (`r`), `fill` (colour or `[c0,c1]` vertical gradient), `stroke`, `lw`, `shadow`, `alpha`, `rot` (about its centre, radians), `pad` (inner padding, default 0.08 x min(w,h)), `id`, `kind`. When `TXA.rec` is on it registers the container: `TXA.UIREG.set(id, {kind, rect:[x0,y0,x1,y1] /*local*/, pad, m:[a,b,c,d,e,f] /*ctx.getTransform() at draw time, after any rotation you applied*/})`. Containers must be registered every frame the audit runs (`TXA.begin` clears the registry).
6. `UI.sign(box, content, o)`: `UI.panel` plus text centred both ways inside the inner box. `content` is a string or an array of lines (`'text'` or `{t, size, fill, weight, font, spacing}`); the block is fitted (shrunk, never squished) to the inner width and height and centred as one block; each line is horizontally ink-centred; lines sit on a consistent baseline grid; registers the container and passes `cid` and `center` to each line. Also `UI.pill(str, cx, cy, o)` (a pill sized to the text with symmetric padding, text cap-centred) and `UI.button` (alias).
7. `UI.page(box, o)`: a sheet of paper (fill, edge, optional fold/shadow, `rot`) with optional ruled lines every `o.pitch` px starting at `o.top`; returns `{rules:[y...], base(i), inner, rect}` where `base(i)` is the baseline for text sitting ON rule `i` (rule y minus a fixed gap of 0.24 x pitch). `UI.onRule(str, x, i, page, o)` draws left-aligned text with its baseline exactly on `page.base(i)`. Registers the page as a container with margins as `pad`.
8. `UI.table(box, cols, rows, o)`: `cols = [{w (px or fraction), align, font, weight, size, fill}]`, `rows = [[cell,...]]` (a cell is a string or `{t, fill, font, ...}`), optional header row; fixed row pitch; every cell fitted into its column minus padding (shrink, then an ellipsis as a last resort, and report it); all cells of a row share one baseline; handwriting or stamps go in their OWN column or a separate overlay row, never on top of a printed cell. Returns `cell(r, c)` boxes. Registers each cell as a container.
9. `UI.stack(items, o)`: a vertical stack of centred blocks for title and end cards. `items = [{t | lines, size, font, weight, fill, stroke, lw, spacing, gap (space after, measured from this block's baseline to the next block's cap top)}]`, `o.cx`, and either `o.top` (cap top of the first line) or `o.cy` (stack centred vertically on its overall ink height). Every line ink-centred on `cx`. Returns the boxes.
10. `UI.rowX(n, x0, x1, o)` / `UI.gridX` helpers: x positions for n equally spaced boxes of width `o.w` between x0 and x1 (equal gaps), `UI.snap(v, grid=8)`.
11. `UI.strike(str, cx, cy, o)`: a label with a strike-through line. Draw the line with `globalCompositeOperation = 'multiply'` in a dark colour (the gate's mask pass ignores non-normal blends, so a deliberate strike does not count as "covered text").
12. `UI.stamp`, `UI.tag` or others you find useful (a rotated stamp box with text, within the tilt limit).
Also export a tiny `UI.sizeOf(str, o)` -> `{w, h}` for layout maths.

Guarantees to test: horizontally centred text lands within 1.5 px of the container centre at zoom 1, 1.5 and 2.0 and under rotations up to 6 degrees; a baseline-placed label's cap band is centred within 2 px; page text sits on its rules (verify by measuring in the gate or with canvas pixel checks); table cells never overlap; letter-spaced centred text has no half-gap offset.

## `ep99.js`: the test episode (not part of any release; keep it small)
Register `EPISODES[99] = { num: 99, v2: true, textGate: true, balanceCaps: true, title: 'UI kit test', TL: window.TIMELINE_EP99, SCENES, layout: 'v2', audio: '' }` behind `if (!window.TIMELINE_EP99) return;` like `ep12.js`. Write `build/ep99/timeline.js` by hand: `window.TIMELINE_EP99 = {fps:30, duration, scenes:[{id, start, dur, clock:'', label:'', beats:{}}...], lines:[]}` (see `build/ep12/timeline.js` for the shape; no spoken lines are needed; captions simply do not appear). Scenes (each ~3 s, `noChyron: true, noScrim: true` is fine for the pure layout scenes; at least one scene must keep the chyron and the scrim so the caption-zone rules are exercised):
- `labels`: every helper with torture strings (long names, descenders `gypsy Jumpy`, all caps, numbers, a 40-character label that must shrink, letter-spaced titles in Bangers and Nunito, italic) in pills, signs and buttons, centred and left aligned.
- `paper`: a ruled page with 8 lines of handwriting-style text on the rules, a table with a header and 6 rows (one cell with a too-long name), a sign-in sheet laid out as a table with a separate signature column, a quiz card (title, three answer buttons, a timer ring).
- `zoom`: the same sign drawn under `zoomTo`-style camera transforms (zoom 1, 1.5, 2) and rotations (0, 3, 6 degrees): the gate must still pass.
- `stack`: a title card (series title, episode pill, subtitle, tagline, small credit) and an end card built with `UI.stack`, perfectly centred.
- `bad`: DELIBERATE violations, one per object, labelled in code: a vertically flipped string, a mirrored string, a string cut by the frame edge, two different strings overlapping, a label that is 12 px off centre in its pill (declare `cid` and `center`), a string tilted 20 degrees, a hero string under the caption zone, a hero string covered by a later-drawn rectangle, a hero string that is 18 px tall.
`tools_gate_selftest.sh`: runs `EP=99 node render.js audit 0.1` (the audit prints grouped issue lines), asserts that NO issue appears outside the `bad` scene, and that the `bad` scene reports each of the nine violations (grep the messages: "upside down", "mirrored", "cut off", "overlaps text", "off centre", "tilted too far", "caption zone", "partly covered" or "hidden", "too small"). Exit 1 with a clear message otherwise. This is the regression test for the gate and the kit.
